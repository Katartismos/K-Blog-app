# Glossary

Standard domain and architectural vocabulary for K-Blog.

### Data Access Layer (DAL)
The isolated internal layer (`frontend/lib/dal/`) responsible for reading from the database using Drizzle ORM and Neon serverless HTTP client. Wrapped with `React.cache()` to provide per-request deduplication within React Server Components and avoid duplicate DB queries.

### Action Wrapper
An in-house higher-order functional pipeline (`frontend/lib/actions/action-wrapper.ts`) that secures Server Actions. Enforces Zod schema validation, optional authentication checks via Better Auth, and security / rate-limiting policies via Arcjet before executing business logic. Returns typed responses `{ success: true, data } | { success: false, error }` to avoid unhandled boundary crashes.

### Server Actions
Next.js App Router server functions declared with `"use server"` used strictly for data mutations (`createPost`, `updatePost`, `deletePost`, `getCloudinaryUploadSignature`). Never used for data fetching into Server Components.

### Stateless Neon Driver
The database connection method using `@neondatabase/serverless`'s `neon()` HTTP client combined with `drizzle-orm/neon-http`. Unlike WebSocket pools (`Pool`), it creates zero persistent connection overhead and avoids connection exhaustion during serverless function scaling.

### Direct Browser Upload
The pattern where image binaries are uploaded directly from the client's browser to Cloudinary CDN via a short-lived HMAC signature generated by the server. Bypasses Vercel's 4.5MB serverless function request body limit entirely.

### Arcjet Live Defense
The security layer provided by `@arcjet/next` running Bot Detection, Web Application Firewall (WAF / Shield), and Sliding Window Rate Limiting (10 requests per 30 seconds) on mutation actions, keyed by user ID (for authenticated sessions) or client IP (for unauthenticated/guest users).
